If you want to know more

Why was it created and what can it do?

My apartment is controlled by a lot of automation — lights, audio, heating, blinds, scenes. Common tools only report "the script ran without error". But a technically successful script does not mean that it was human-pleasing. The radio can start three times in a row, the light can turn on full blast at night, the heater can heat even when no one is home — and it all "technically went OK".

Resident Auditor takes a different view. It takes the saved logs of the house for a specific day and asks humanly for each situation: Was the morning peaceful? Did the lights react to movement and did the blinds have priority? Was the radio left on or playing when I left? Was the heating reasonably warm? Did something wake me up in the night?

Key rule: never PASS without evidence. If there's no evidence that something went well, it doesn't get a green light — it gets a WATCH. And vice versa: routine, harmless events are not counted as a problem so that they do not arise false alarms. The goal is a credible verdict, not pretty statistics.

It doesn't change anything. The tool is clean read-only — just reads the logs. It doesn't interfere with the house, it doesn't fix anything, it doesn't run in the background. I run it manually when I want to know how the house behaved.

Detailed list of features
  • 10 areas of life in an apartment — morning, night movement, audio & voice messages, lights & blinds, bathroom, heating, device reliability and system stability. Each has its own "evaluator".
  • Verdict according to the evidence: PASS / WATCH / FAIL — green only with positive proof of correct behaviour; otherwise to track; red only for a real problem.
  • No false PASS or false alarm — distinguish a real action from a routine check, so it doesn't report a problem where there isn't one.
  • Suggest a next step for each problem — když něco selže, vznikne „úkol k řešení“ s důkazy (čas, co se stalo, dopad na obyvatele) — ale oprava se nikdy nespustí sama, čeká na moje rozhodnutí.
  • Audit of a specific day — I run it on the selected day and get a clear report; ideal as a control after every home improvement.
  • By hand, safely — no autostart, no home invasion, just reading.

Availability and current status

Development journal
  • Timezone reading fix (July 2026) — In the backup procedure for recalculating the time of logs, a bug was found in the folding of the time zone text, which caused part of the tests to crash. After the fix, the offline test suites are running in full again (9/9). Features and versions are not changing, this is maintenance.
  • v0.1 done — calibration on real data (June 2026) — The tool reads real logs of the house and gives PASS/FAIL for lights, bathroom, heating and morning according to real actions (not according to the number of lines in the log). Ověřeno na dvou reálných dnech: 9 oblastí zelených s důkazem, 1 ke sledování — 0 falešných poplachů.
  • Correcting false alarms — Turned out that routine "check" events (guard checked something, everything OK) must not be counted as a problem. An added "semantic layer" distinguishes a real action from a routine — thanks to which the tool does not report an alarm where there is none.
  • Connection to real logs of the house — The house has been keeping detailed records of behavior for a long time. The tool connected to them (read only) and started interpreting them correctly — including time zones and context (phase of day, presence, brightness).
  • Ten raters (plugins) — Gradually added areas: morning and system crashes, then audio/lights/bathroom, then heating/night/dashboard/equipment. Each is self-contained and testable.
  • Basic principle from the beginning — Never PASS without evidence. Technical success is not enough. Read-only, manually triggered, never enters the house without my permission.
