If you want to know more

Why was it created and what can it do?

Why it was created: I tried several diet apps (MyFitnessPal, Yazio, Lifesum…) and all of them pissed me off. Either they wanted an account and sent me ads, or they didn't know Czech food, or they were pushing a specific nutritional philosophy. This application is running only in my browser — the profile lives in localStorage (browser memory), no server can see my weight, calories or what I eat today.

How it works: I enter my height, weight, age, activity. The application calculates how many calories I need per day (Mifflin-St Jeor formula for resting metabolism + multiplier according to activity). If I want to lose weight, he recommends an asymmetric deficit (lighter by a few hundred kcal). If you want to gain muscle, you also try to choose recipes with a higher protein ratio.

Weekly box schedule: The application goes through a database of about 21 recipes and compiles 7 days x 5 meals (breakfast, snack, lunch, snack, dinner) so that the daily amount of kcal falls within ±10% of the target. Then it generates a shopping list — it adds up all the ingredients for the week and divides them into categories (meat, dairy, vegetables, ...). Export to CSV or print.

Optional Roll: If I have a customer at Rohlík, I can have the agent (Claude) prepare a cart proposal from the weekly plan, insert the JSON into Settings and the application will display the price vs the minimum order vs the delivery price. But I always confirm the order manually in Rohlík UI — the application cannot physically order or pay (defense-in-depth, 5 layers of protection, 14 PII blacklist rules).

PWA = works offline: After the first opening, it is saved in the browser and works even without the Internet. I can install it as a desktop app on Windows via Edge. No app store updates, no notifications, no telemetry.

Detailed list of features
  • Auto-generated weekly schedule — Combo search algorithm for 7×5 meals, daily kcal within ±10% of target. Penalizing repeating recipes for variety.
  • BMR/TDEE calculator — Mifflin-St Jeor formula for resting metabolism + activity multiplier. Asymmetric deficit/surplus according to weekly weight change.
  • Recommended destination + banner — When the recommended kcal target is moved according to the metrics, the app prompts "Use Recommended" (never a silent change without the user's knowledge).
  • Weight tracking — Custom SVG graph without external library, history in browser's localStorage. No medical claims.
  • Optimizer for weight loss/gain — If you want to lose weight, choose recipes with a higher protein ratio. If you gain muscle, the same + stricter adherence to the kcal target.
  • Integration roll (optional) — The agent prepares a basket proposal as JSON, you see the price vs minimum vs delivery. You always confirm the order manually in Rohlík.
  • Shopping list with export — Aggregates ingredients from the weekly plan, divides into categories, CSV export or print.
  • PWA + offline — Works without internet after first download. Installable as a desktop app via Edge / Chrome.

Development journal
  • 1.0.2 — faster save with database mirroring enabled (October 2026) — the first release since 1.0.1 that brings something. Data mirroring to the local database can be turned on in Settings; the application then overwrote everything every time it was saved, even what hadn't changed. With a fridge full of pictures, it was megabytes adding a single item and you could tell. Only what I have really changed is sent newly. Smearing to the mirror is prescribed as reliably as before — I verified this separately, because this is where it is easy to slip and return something you deleted. Those who do not have mirroring turned on (the default state) will not know any difference. Under the hood: the repository access helper code was copied five times in different files, now it's in one place. 1080 unit tests, e2e 76/76. A note for fairness: in the first run of the tests, one performance test (plan generator) exceeded the time limit and crashed; it wasn't a regression — the generator code didn't change at all, it passed the test in isolation and the second full run was 1080/1080. The machine is simply slower than in the summer; I don't raise the ceiling on purpose. Even before the release (10/19), e2e tests were added for Refrigerator and Preparation, two modules that did not have any.
  • 1.0.1 — fix: helper server kept running (August 2026) — when you closed the application, the process continued to run in the background meal-planner-server.exe and had to manually quit in Task Manager. A second problem followed: that forgotten server was holding the port, so the next application launch would encounter it and show an ugly technical dump window. Both are gone — and now the server will shut down even if the app crashes or you force kill it. If the port is still occupied by a completely different program, the application will no longer crash with an incomprehensible message, but will write in a human way what happened. A note for fairness: the bug was in the app from 0.8.0, it just didn't show up until 0.9.14 — a security fix at the time (the server stopped sharing the port with anyone else) revealed it. That adjustment was correct and remains so.
  • 1.0.0 — first release (August 2026) — after a year of beta, the application is declared complete. No new features from 0.9.17; the designation changes from "beta" to "final version" and is shown in the header v1.0.0 · final. I consider the menu, boxes, shopping, Pantry, schedule monitoring, deposits and data from the watch to be finished and I am not going to rebuild them. A disclaimer that is fair to say straight away: content of the exercise part — all 17 exercises — did not pass peer review. It was written by a developer, not a trainer or physical therapist. Therefore, the application will no longer create a training plan during pregnancy and after childbirth, in the case of heart and blood vessel diseases, metabolic diseases, ongoing rehabilitation, eating disorders, in children and adolescents, in the elderly with a risk of falling, and in case of restrictions from a doctor. "Final Version" refers to the cash and stability of the application, no for professional approval of exercises — and it is also written in the application, in the Trust Center, where it does not disappear after closing the window. When the revision is done, the groups will be unlocked with a separate release.
  • 0.9.17 beta — maintenance release (August 2026) — no new feature or fix. Only the developer limit on the size of the package has changed, which does not enter the installation at all. Issued to verify that the entire build and distribution chain works with the new limit. If you were wondering why your application updated and you don't see anything new — this is the reason.
  • 0.9.16 beta — watch and phone data (August 2026) — I export data from Apple Health (export.xml) or from Health Connect (JSON) and upload them in Fitness Settings. The application reads steps, active energy, heart rate, sleep and training from them. When I have for today measured burned energy, shows it instead of his estimate and adds how much the estimate differed — the estimate never overwrites the measured value, even if it is higher. Repeated import of the same file will not duplicate the data. Connecting directly to HealthKit or Health Connect is not possible: they are native phone interfaces and Meal Planner runs on Windows, so importing from a file is the only way there is. Health data remains on the computer. 1077 unit tests, e2e 73/73.
  • 0.9.15 beta — Fitness module (August 2026) — training and food finally in one place. I plan my workouts by hand or have the whole week designed based on goal, equipment, time and what hurts me; with every design I can see why it looks the way it does, and the same assignment always gives the same plan. I record the sets I've worked out, I'll tell how I feel with a daily check, and if it's a bad day, the app advises me to cut back or take time off — no one blames me for a missed workout. Training shows up on the same calendar as meals, and I can optionally have more energy on training day without changing my weekly intake (protein keeps the target every day). A short readiness to move questionnaire is completed before the first plan; if something comes out of it that the application is not supposed to decide about, it doesn't build a plan and say why. In the case of pregnancy, heart and blood vessel disease, rehabilitation, eating disorders, children and restrictions from the doctor, he does not plan at all — the rules for these situations must first be approved by an expert. The content of the 17 exercises has not yet been reviewed by a trainer or physiotherapist, it was written by the developer and the application writes it out loud for each exercise. 1050 unit tests, e2e 70/70.

An incomplete backup restore now completes itself on next launch (previously it could hang and block data loading), restore restore cleans up after itself, and deleted items don't come back even after clearing browser data.
