How the household is managed

Movement, time or coming home will trigger the request. The control rules evaluate the situation before changing the light, heating or other equipment. Below I describe how these steps are separated and why the system is better controlled.

Technical details

All logic in one place. Flow is the trigger, the script is the brain, the router is the switchboard, the device is the output.

Trigger (time, sensor, button)
Script
Logic + multi-signal eval
Request

Priorities + addressing

12 rules that I have introduced

Each rule arose from a specific incident, not from a theory. Here are all that hold the system together today.

REUSE FIRST

Before creating a new entity (script, flow, variable), check whether a similar one already exists. Refactor > new code.

SCRIPT-FIRST

Flow = trigger + set variable + run script. No logic in Flow cards. The logic in the scripts is versionable, debuggable, testable.

DEVICE MAP

No hardcoded device name. All over sh_device_map_v1. Renaming a device = one change, not 20 broken scripts.

MULTI-SIGNAL

No critical decision from a single sensor. Always 2+ independent signals (FP2 + Z-Wave motion, button + geofence).

SLEEP RESPECT

No TTS, loud actions or lights at sh_spim=yes. Exceptions: morning briefing, critical alarms.

PRIVACY INTERLOCK

Blind open → open space lights blocked. Small apartment, passersby can see inside. Aquarium effect.

IDLE RESET

Each temporary request must be reset to idle. No reset = stuck pipeline + no radio in the morning.

WINDOW GUARDS

Triggers have time windows — morning routine 3am-10am, nighttime 10pm-6am. Outside the window, the script refuses to continue.

NO THROW

Never throw new Error(). Always log + return false. Throw crashes before cleanup, leaving variables in an inconsistent state.

VARIABLE CACHE

Each script caches variables (_varCache + _loadVars()). No cache = SIGABRT on 200+ variables.

IDEMPOTENCY

setCapabilityValue only if the value actually changes. Blind set = cascade of Flow triggers and unnecessary load.

NO REGRESSION

Before modifying an existing script: read the whole, verify the caller, minimal change. "It's worked before" = don't reach beyond a strong need.
