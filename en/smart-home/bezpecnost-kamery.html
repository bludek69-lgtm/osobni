🏠 Experience · Security and cameras

Security which he's not paranoid

Sensors monitor open windows, doors and movement. Household distinguishes whether I am at home or away; it alerts me in case of an unusual condition. It is important to limit unnecessary alarms and to know what actually happened.

Technical details

Sensors on windows and doors, multi-zone motion detection, away/home status logic and a Brain Guardian meta-layer that monitors whether the house is behaving as it should. The goal is not to sound an alarm for every sparrow outside the window — the goal is to know when something is wrong and fix it yourself where possible.

What does it do?

Three layers of detection + meta-layer

Layer 1 — physical sensors: door/window contacts on key windows, PIR motion in the kitchen, mmWave presence in the open space, motion in the bathroom. Each sensor has capabilities in Homey and its own flow trigger. Nothing exotic, just classic detection.

Layer 2 — stateful logic: away/home preset switches the behavior of the whole house. The Geofence detects the exit, the presence scripts confirm, and all zones are switched — heating to 16 °C, lights blocked, or the cleaner reacts to an open window.

Tier 3 — Brain Guardian: meta-supervisor 5-script module that monitors if the state of the house is as expected. Monitors stuck priority gates, boiler running for more than 4 hours, long-term non-updated sensors, ghost state variables.

Daily operation

How security reacts to situations

Passive most of the time. It only reacts when the situation changes fundamentally.

  1. At home

    Idle state

    Sensors log activity, motion → lights, presence → audio context. No push notifications, no alerts. Brain Guardian runs once every 15 min, checks for consistency.

  2. Departure

    Away preset

    Geofence detects the exit → preset = away → heating 16 °C, lights blocked, or the robot starts the vacuum cleaner. Condition sh_rezim_doma='pryc' gate all zones — light_router rejects, audio brain goes silent.

  3. Return

    Home preset

    Geofence + first motion in the apartment → preset = home → heating boost to schedule slot, lights released, multi-signal confirm (geofence + motion in 5 min) confirms return. Single-signal is ignored (false trigger protection).

  4. Anomaly

    Brain Guardian alert

    When cron detects stuck state (priority='tts' for more than 1 min), boiler running for 4+ h, sensor not updated for 24+ h, ghost var, it issues an alert to EventLog. Critical alerts (anti-freeze, water leak) go through the safety bypass.

Scenes

Five situations, five answers

It is mostly launched without user action — from the context.

Open window

Door/window contact on the window opens → flow turns off the air cleaner (unnecessary to filter outside). Restores after closing. Real incident 26.4. — UUID change after re-pair, 3 flows broken, the cleaner did not turn on.

Departure

Geofence GPS leaves the home zone → multi-signal confirm with 5 min delay (eliminates false trigger with neighbors) → preset = away → cascade to all subsystems.

Return

Geofence enters + first motion in 5 min → preset = home. The heating will match the current schedule slot, audio released for briefing/comfort.

Anomaly detect

Brain Guardian cron 15 min → checks 12 invariants. If something off, expose brain_guardian_status variable + EventLog alert. Push notifications are still manual.

Critical bypass

Anti-freeze (zone below 7 °C), water leak, gas detection → ignores sleep guard, priority engine, all other rules. The heating switches on, an alert is sent to the speaker in the bedroom.

For the tech-savvy

What's going on under the hood

Multi-signal confirm, Brain Guardian invariants, UUID stability lessons.

Multi-signal confirm (why single-signal is not enough)

Geofence GPS on a mobile phone has a range of 30-50m. When I drive by the house or am at the neighbors, the GPS can fall into the home zone even when I am not at home. Single-signal by trigger preset=home → heating boost → unnecessary consumption.

Multi-signal confirm: geofence_in_home + first motion in apartment in 5 min window → home preset. Without motion confirm, preset=away remains. Symmetrically for departure: geofence_out + 0 motion in 10 min → away preset (= I'm really away).

Brain Guardian — 12 invariants

Cron sh_brain_guardian_v1 checks state consistency every 15 min:

  • Stuck priorities: active='tts' AND age > 60 s → reset
  • Boiler runaway: boiler_state='on' AND runtime > 14400 s → forced off
  • Sensor still: lastUpdated > 24 h → battery alert
  • Ghost state: priority_active='tts' and no recent TTS event → reset
  • Schedule sanitation: target_temp < min_temp_ever → reset to default
  • Antifreeze: any zone < 7 °C → forced on (overrides mode)
  • Sleep consistency: sh_spim='yes' AND motion_count > 3 in 5 min → wake suspect
  • UUID orphan: device_map ref unavailable → log to EventLog
  • Schedule overlap: 2+ slots overlapping in time → first-wins + log
  • Variable type: number var with string value → reset to default
  • Future timestamp: until_ts > now + 7 d → expire (dirty data)
  • Cron drift: scheduler last_run > 600 s → flow not firing alert
UUID change after re-pair (silent fail)

After replacing the battery / re-installing the device Homey will generate new UUID. Old UUID in device_map and flow trigger cards = orphan reference, no error, just silent fail. Real incident 26.4. — Door/Window Sensor Dining room1 overpaired, 3 flows broken, the cleaner did not turn off when the window was opened.

Diagnosis: GET /api/manager/devices/device/<old_id> → 404.
Fixed: bulk OLD→NEW swap via PUT of each affected flow.
Prevention (backlog): tools/find_orphan_device_refs.py prevention scanner that runs before every commit.

Sleep state guards (sh_spim)

Central sleep state variable sh_spim ('yes' / 'no'). When 'yes':

  • Priority engine days for light request → dark
  • Audio brain days for TTS (except critical alerts)
  • Heating night slot has already been applied to the scheduler → lower temperatures
  • Robot vacuum cleaner blocked
  • Brain Guardian increased tolerance for motion (anti-false-positive)

Set points: Sleep Manual button (Cubo), Wake up Kitchen motion, Phone geofence. Never do not delete set_asleep / set_awake actions in flows as "duplicate" — sync with native Homey presence (Mobile UI, HomeKit, Google Home).

Critical alert bypass (safety)

Some situations have to fly through sleep guard, engine priorities, everything. Implemented via sh_safety_bypass='yes' short circuit:

  • Antifreeze: any zone < 7 °C → heating forced on, alert
  • Water leak (planned): Aqara water sensor → closes the supply, alert
  • Gas leak (planned): combined sensor → turns off the boiler, alert
  • Smoke (planned): smoke sensor → turns off all power consumers

Bypass is a read-only flag — no script resets it, only the safety event log handler.
