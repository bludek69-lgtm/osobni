Smart sockets and consumption measurement

Smart sockets help monitor the consumption of specific appliances. Here I distinguish between socket metering, switching and metering in the switchboard and describe how I use their data.

Technical details

Thirteen smart plug devices with power metering, one Z-wave dual-switch with native metering as a reserve for the heating circuit, and from May 12, 2026 also Shelly Pro 3EM as the final 3-phase meter in the switchboard. Finally, it is known how much the house actually takes, plus granular per-device measurement where a socket is enough.

What does it do?

Per-device measurement as a cheap proxy

Smart plug with power metering = a classic socket that replaces the original one + measures how much the appliance takes after it. Price ~500–800 CZK, advantage: granular data per appliance. Refrigerator, computer, monitor, audio system — each has its own socket, each has its own number.

Capabilities API via Homey: onoff (boolean — control), measure_power (W — real-time current), meter_power (kWh — cumulative counter), measure_voltage (V — diagnosis), measure_current (A — diagnosis).

Measurement is passive — flow trigger on change, the sampler script iterates devices every 5 minutes and logs the values in the EventLog. From this, the daily integration (∫ W dt) gives kWh per device. Plus cumulative counter meter_power refines through restarts (the driver remembers).

Use-cases

Where measurement comes in handy

Not all sockets are just for stats.

  1. Continuous

    Energy tracking

    Refrigerator, freezer, computer idle — continuous baseline. From the daily integral, you can see if there is any hidden drain (plug on but no one uses it invisibly → free 50 W per day).

  2. Auto on/off

    Schedule-based

    Some appliances have a schedule — for example, a washing machine "auto-start at 10:00 p.m. (low tariff)". Robot vacuum cleaner "at 14:00 during the week when no one is at home". Toggle over onoff capability + schedule var.

  3. Remote

    Remote control

    From the dashboard or mobile app — turn off the PC remotely after work, check if you forgot the iron. Combination with motion (iron + 0 motion 1 h → auto-off) in the plan.

  4. Anomalies

    Power spike detection

    Brain Guardian: if measure_power of one device > 200% of typical average for 5+ min, anomaly alert. Possibilities: failing motor, out-of-tune cooler, or just abnormal usage.

Hardware in operation

Specific sockets

Mix of Z-wave (Fibaro Wall Plug) and Wi-Fi (Tuya / Shelly Plug S).

Fibaro Wall Plug

Z-wave · onoff + measure_power + meter_power

Flagship. Z-wave (local), full capability set. The LED ring indicates the current consumption in color. The price is ~1,200 CZK, but the reliability and metering quality are worth the premium.

Shelly Plug S (×N)

Wi-Fi · onoff + measure_power + voltage

Cheaper Wi-Fi alternative (~500 CZK). HTTP REST API and MQTT, local (no cloud required). Installed on PC, monitor, lamps in the study.

Tuya plugs (×N)

Wi-Fi · onoff + measure_power · cloud-dependent

The cheapest (~250 CZK). Cloud dependency (sometimes ~1 s latency). Power metering accuracy ±5%. Used on low-priority appliances — chargers, ambient lamps.

Fibaro FGS-223 (reserve)

Double Switch 2 · Z-wave · power metering

Z-wave double switch with native power metering capability. Currently NOT CONNECTED — in reserve for the heating circulation pump (heating Phase C+) or boiler. Memory: reference_unmapped_devices_intentional.md.

Shelly Pro 3EM LIVE

3 CT clamps · 3-phase · Wi-Fi · 192.168.1.xxx

Installed on May 12 in the cabinet. Three current coils on 3 phases measure consumption and possible production (export to the grid) in real time. The RPi asks it every 30 seconds with an HTTP request and saves 17 values ​​to Homey (per-phase W/V/A, total sum, consumed and returned kWh, temperature). Finally, a hard source of truth about how much a house really costs.

2x Shelly Plus PM Mini Gen3 LIVE

plug power meter · Wi-Fi · Matter ready

Two new measuring sockets in the kitchen — coffee machine and stove in line. Small, cheap (~470 CZK/piece), Matter ready. They added 11 original plug-meters to 13 in total. It mainly serves to know exactly how much the kitchen actually takes in individual parts of the day.

Water valve Planned

Aqara · auto-close on water leak

It's not a socket, but it shares the same category (force action via capability). Aqara motorized ball valve on the main water supply. Trigger water leak sensor → auto-close + alert.

For the tech-savvy

What's going on under the hood

measure_power vs. meter_power, sample integration, anomaly detection.

measure_power vs. meter_power (difference)
  • measure_power (W) — current consumption in watts. Real-time, sample via flow trigger or manual getCapabilityValue. Use: instant view, daily curve, anomaly detection.
  • meter_power (kWh) — cumulative counter since the last device reset. It is incremented in the device firmware, persists through Homey restart. Usage: cumulative energy per period (difference meter_now − meter_baseline).

For daily kWh: kwh_today = meter_power_now − meter_power_at_midnight. The midnight snapshot saves the baseline. Independent of the sample interval = invoicing accurate.

Sampler script (sh_plug_sampler_v1)

Cron 5 min: 

// sh_plug_sampler_v1
const plugs = await getDevicesByDriverIds(['fibaro-wall-plug', 'shelly-plug-s', 'tuya-plug']);
for (const plug of plugs) {
  const power = await plug.capabilitiesObj.measure_power?.value || 0;
  const meter = await plug.capabilitiesObj.meter_power?.value || 0;
  await logEvent({
    script: 'sh_plug_sampler_v1',
    event: 'plug_sample',
    device: plug.name,
    power_w: power,
    meter_kwh: meter,
    timestamp: now()
  });
}

Output to EventLog JSONL on SSD (from 27.5.2026; formerly Google Sheets). From this, per-device daily/weekly/yearly curves for the dashboard tile can be constructed.

Anomaly detection (power spike)

Brain Guardian invariant for plugs:

  • Rolling 7-day average measure_power per device — baseline
  • Current 5min sample > 200% baseline for 3 consecutive samples (= 15 min) → anomaly alert
  • Plus typed anomalies: refrigerator baseline ~50 W, above 150 W → compressor non-stop (perhaps broken cooling); PC baseline 80 W idle, over 400 W — gaming session

Alert is a read-only flag, no auto-actions. The user must verify (push in the plan).

Auto-off on motion = 0 (planned)

Planned feature: iron / electric kettle / hot air gun → smart plug + watchdog. 

// pseudocode
if (plug.power > 100 W &&
    motion_zone[plug.zone].lastMotion > 60 min ago &&

  await plug.setCapabilityValue('onoff', false);

Threshold per device — not all high-power appliances need auto-off (no refrigerator, of course). Whitelist via sh_cfg_plug_auto_off_devices.
