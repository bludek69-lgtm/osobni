Motion sensors and environment

Various sensors recognize movement, the presence of a person, an open window or the amount of daylight. Everyone has different capabilities and limitations. Below is an overview of their use and what to watch out for when reading the data.

Technical details

Overview of detection — where and how the house senses reality. mmWave radar for a quiet person, classic PIR for movement, contact sensors on windows, lux for daylight. Each type has a different use-case, different limits and its own battery consumption.

What does it do?

Detection layers + data path

Sensors are input layer of the entire system. Without them, the system does not know if someone is in the room, if it is dark, if the window is open. Each sensor has a capability in Homey (e.g. alarm_motion, alarm_presence, alarm_contact), which the flow trigger reads and sends the event to the scripts.

Architecturally sensors they never interfere straight to the action. Instead, they write the status to request variables (e.g. sh_light_request='on') and the request-first pipeline decides whether the action will take place. This enables sleep guard, privacy guard, priority engine — and most importantly testability.

Most sensors are battery. Lifetime typically 1-2 years. Brain Guardian is watching lastUpdated timestamp — when the sensor has not updated for 24+ h, alert in EventLog (battery suspect). Re-pair will generate after replacing the battery new UUID — flow trigger of cards with old UUID silent fail, fix requires bulk swap.

Types of sensors

Four categories, four roles

Each detects a different thing. Together they give a complete picture.

  1. Presence

    mmWave radar (FP2)

    He sees a calm person — sitting, breathing, micro-movements. Plus movement. Capabilities alarm_presence. Price ~1,500 CZK. Limit: the detection zone is not 100% accurate, it sometimes flashes to False, hence the triple-sensor guard.

  2. Motion

    PIR (Fibaro Z-wave)

    Classic passive-infrared. Detects temperature change (= motion). He does not feel a calm person. Capabilities alarm_motion. Cheap (~600 CZK), reliable, long battery life. Ideal for kitchen, bathroom.

  3. Contact

    Door/Window contact

    Magnetic contact on window/door. Capabilities alarm_contact. Simple, cheapest (~350 CZK), without false positives. SNZB-04 has a known firmware bug (deep-sleep failure) — Aqara P2 replacement.

  4. Environmental

    Lux + temperature

    Lux sensor for daylight (controls lighting), internal temperature sensors in each TRV for heating. Capabilities measure_luminance, measure_temperature. Continuous, not event-based.

For the tech-savvy

What's going on under the hood

Zigbee vs. Z-wave, battery management, UUID stability.

Zigbee vs. Z-wave (why both)

Zigbee 3.0 (2.4 GHz) — Aqara FP2, door/window, lux. Cheaper sensors, mesh in own space, Aqara hub-free integration via Homey Pro 2026. Weaker range, shared band with Wi-Fi.

Z-wave (868 MHz EU) — Fibaro PIR, FGS-214 (boiler), 3× FGT-001 TRV. More expensive, but dedicated band, good range through walls, powered devices work as repeaters for mesh.

For battery motion sensors, Zigbee would also be OK, but Fibaro PIR has better firmware reliability than the cheap Aqara variant (test: 6 months, 0 false positives).

Triple-sensor guard for presence_off

FP2 sometimes falsely flashes on alarm_presence=false (cooldown / sensitivity). 15 min flow delay → presence_off event → router would like to turn off the lights. At that moment, the user was already back. 

if (presence_event === 'off') {
  if (motion.alarm_motion === true) → keep on (motion_active)
  if (presence.alarm_presence === true) → keep on (presence_recovered)
  if (max(open_presence_ts, open_motion_ts) > now - 5min) → keep on (recent)
}

Implemented in sh_open_space_router_v1 v1.18. Without this guard, the light would flicker every 15 minutes while sitting quietly.

Battery management (lastUpdated tracking)

Brain Guardian cron 15 min iterates sensors with capability measure_battery a lastUpdated time stamp:

  • battery < 20% → battery_low alert, log to EventLog
  • battery < 10% → battery_critical, push (when implemented)
  • lastUpdated > 24 h → sensor still, possible dead battery
  • lastUpdated > 72 h → sensor unreachable, suggest re-pair

SNZB-04 (door/window) has a friend deep-sleep firmware bug — falls into unreachable even with a full battery. Aqara P2 (Matter/Thread) replacement planned.

Stability UUID (re-pair = new UUID)

After replacing the battery / re-installing the device Homey will generate new UUID. Old UUID in device_map / flow trigger cards = orphan reference, no error, just silent fail.

Real incident 26.4. — Door/Window Sensor Dining room1 overpaired, 3 flows broken, the cleaner did not turn off when the window was opened. Diagnosis: GET /api/manager/devices/device/<old> → 404. Fix: bulk swap PUT.

Backlog: tools/find_orphan_device_refs.py prevention scanner — before each commit, checks if all device_map references are live.

Lux thresholds + hysteresis

Open space lux control uses two thresholds + hysteresis for stability:

  • sh_cfg_lux_open_space_on = 120 — below that they turn on (if presence)
  • sh_cfg_lux_open_space_off = 400 — above that they switch off (enough daylight)
  • Between 120 and 400: keeps current state (no on→off→on flikr)

Lux sensor reads from sh_lux_jidelna or sh_lux_kuchyne_xiaomi (max of both, pessimistic estimate — most darkness in the zone).
