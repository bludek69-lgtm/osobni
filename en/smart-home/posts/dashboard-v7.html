Dashboard V7 — new layout and visual control

The V3.7 → V4 → V5 → V6 → V7 redesign cycle is complete. The dashboard, which today runs on three screens (32" monitor 2880x1800, 14" laptop 1920x1080 and RPi kiosk WaveShare 1024x600), went through six complete iterations in two weeks.

This post summarizes what changed, what worked, what didn't and why we are finally pausing dashboard work.

Key changes in V7

  • Sidebar 240px as primary navigation. Below 1280px it collapses to 64px (only icons), below 768px it hides completely in the hamburger menu.
  • 5 status pills in the topbar: MODE, SECURITY, ALARM, AI, WEATHER. Each with its own status color (green OK / yellow warning / red alarm) and a tooltip with details.
  • Premium CSS layer (~20 KB). Glass cards with backdrop-blur, subtle gradient borders, glow accents on hover, uniform typography across all 6 dashboards.
  • Preserved hard locks: 309+ onclick events, 200 flows, 136 scripts. No JS handlers were renamed, no IDs were changed — the redesign is purely visual.

Three screens, three variants

Shared architecture (same HTML structure, same JS handlers), different resolutions and optimization for physical context:

  • 2880×1800 (32" monitor) — full sidebar, all 14 pages, detailed zone views, real-time graphs.
  • 1920×1080 (14" laptop) — sidebar collapses to 64px below the breakpoint, the layout prioritizes the daily view.
  • 1024×600 (RPi kiosk) — compact 4-col grid, 8 narrowed pages, larger touch targets (min 44px), no hover states.

What worked

Convention v5-* ID prefix. After V5, we introduced that new components are prefixed according to the iteration in which they were created. With the V7 review, you immediately see what is fresh and what is stable — and it is clear that the old IDs (without the prefix) do not overlap.

Shell math before detail. We started each iteration by calculating the grid system (how many cells, what breakpoints, how it is reduced) BEFORE drawing the components. It saves half a day of rework.

Hard locks list. Before each redesign, a list of IDs and handlers that MUST NOT be changed was drawn up. Then the validation script after the redesign goes through the HTML and compares. No regressions.

What didn't work

V3.7 → V4 as single-shot. First attempt at a big leap (sidebar + topbar + new grid + new typography) all at once. The result was broken, we had to go back and iterate smaller steps.

“Everything looks good in Figma. Real device test is necessary. The RPi 1024×600 looked 1280×800 ok in the simulation, but was vertically squeezed on the real WaveShare display. Only after the physical test was the variant created smart_home_v3_rpi_1024.html.

Why are we pausing the dashboard?

The dashboard is in working condition, looks good and holds the hard locks. Marginal value decreases with each subsequent iteration — further adjustments are just micro-tuning at the level of individual pages (Wave A/B/C in the backlog).

Meanwhile, a higher priority appeared: Brain Guardian V1. A meta-layer on top of the entire system that detects ghost values, verifies the expected state, and blocks broken deployments. There is now a real architectural value.

Dashboard work paused, not abandoned. Wave A/B/C remains in the backlog for page-by-page micro-iterations as space permits.
