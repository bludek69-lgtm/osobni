Dashboard Config Center + Weather restore — 8 waves in one day

May 15 evening. After the R2-R6A series of Homey runtime fixes, we moved to the other side — the dashboard. Three outputs, three resolutions: WaveShare 10.1″ 1024×600 (RPi kiosk), 14″ notebook 1920×1080, 32″ master 2880×1800. The goal: a stable render, no silent-fail buttons, and most importantly no entry of Czech literals like doma, pryc, ano into logical variables.

Wave 1 — canonical enum guard

Before wave 1, the dashboard could write to sh_rezim_doma value 'doma', while the rest of the system (sh_morning_brain, sh_audio_brain, sh_light_router) worked with 'home'. Silent mismatch — no error, just the automation didn't do what it was supposed to. The same with 'pryc' vs 'away', 'ano' vs 'yes', 'strong_yes' vs 'yes'.

Wave 1 added by helper __CANON_ENUMS directly into HTML. In front of everyone writeVar the dashboard will compare the value with the enabled enum (English tokens). If it finds a Czech literal or true/false, blocks write and logs. 9 forbidden literals in total.

Wave 2A + 2B — weather restoration

After the recent RPi migration to SSD, the kiosk renderer reverted to the old weather version (OpenWeatherMap proxy via Homey), which has since stopped working. The diagnostic wasn't a bug code — it was deploy-channel regression. SSD rebuild overwrote the patched canonical file with an older OWM file.

Wave 2A: cache-first renderer (reads directly sh_weather_3d_json from Homey logic vars) was re-deployed on the RPi via SSH. Wave 2B revived cron sh_weather_yr_bridge_v1, which downloads yr.no JSON every 10 min and writes it to the same var. No API keys, no OWM, no proxy hop — yr.no is free and stable.

Wave 3 — blind = PURE LUX truth

The blind in the Dining Room had two contradictory conditions: sh_house_state and outdoor lux. When sh_house_state was 'home_normal', short-circuit and blind at the top regardless of lux. But in reality it caused a drift — the blind remained up even at night when the lux was 0. Wave 3 removed that short-circuit. Now the only truth is lux + hysteresis (R3 throttle deploy from 5/13 remained in place).

Wave 6 — desktop parity

v7_1920 (notebook) and v7_2880 (32″ master) received the same __CANON_ENUMS guard like RPi. Three outputs, identical write contract.

Wave 4A → 4B-6 — Config Center

Here was the biggest change. Instead of each config tile having its own inline write logic, Wave 4A added DASHBOARD_CONFIG_SCHEMA object + helper writeVarValidated(varName, value). Schema defines for each logic var: type, min, max, enum, cross-field dependencies, soft warnings.

Wave 4B gradually expanded the scheme from 18 entries (4B-1) to 128+ entries (4B-6). Covers: morning routine cfg (alarm window, kaffe immediate, score boost), heating cfg (target_temp s min:5 for frostsave 7°C, manual_override_temp s min:-99 for sentinel), audio cfg, light cfg, occupancy thresholds, vacancy guardian timeouts, blind lux thresholds, energy budget caps, scene engine modes (idle, reset, romantika, relax, kino, vareni, work).

writeCfg dispatcher unified all config write paths. Currently running in soft-reject mode — log warning, but write starts. After a 24-hour soak, we switch to hard-reject (true block). Final RPi sha: e3216213e4b9f73772c1a555d790cd5e411bac5b2031c290ffaf36e791bd7aec.

What I avoided in the process

B11 misdiagnosis: I wanted to add a new helper at the beginning setHeatingBoost(30) to the dashboard. But while reading the live source, I found out that it already exists and is correctly wired. No new code, REUSE FIRST, revert. Likewise, the scene engine — they wanted to offer dashboards comfort a night as scene IDs, but the engine does not recognize them. Seven IDs only. Wave 5 (Homey-side scene enumeration) is scheduled but not tonight.

What next

Overnight soak. Automatic in the morning OVERNIGHT_SOAK_REPORT_2026-05-16_0600.md fire-Sun at 06:00 Prague. After it: Wave 4B hard-mode flip, R6A morning verify (reads EventLog for last morning routine), then R6B (Gemini brain + morning score heartbeat) and R5 SIGABRT main hunt (~7-8 crashes/h baseline, root cause not resolved).

The dashboard is now in a state where it refuses to write nonsense. This is the first milestone since I don't have to monitor enum values ​​manually when reviewing pull requests.
