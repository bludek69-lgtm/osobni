📦 Devices · Buttons and controls

Controlling without applications

I don't always want to look for the phone. The cube and physical buttons let me change home mode or volume right from where I am. Below are the individual gestures and their assigned functions.

Technical details

User input without having to open the phone. Aqara Cube T1 Pro as the primary gestural controller — a six-sided cube where each side = different mode, rotation = volume, tap = trigger. Plus Sleep Manual button and physical buttons like fallback.

What does it do?

Physical controller as primary UX

A smart home with a mobile app as the only UX is unusable — when I have my hands in a test, or when I'm just getting up, no one is picking up the phone. Therefore, a physical driver like primary input layer: Aqara Cube T1 Pro standing on shelf, one hand, different gestures = different actions.

Cube has three types of gestures: flip (turn to new page — cube_face capability value 1–6), rotate (roll the die on the same side — cube_rotate emitting +/- delta), tap (tap — cube_tap events). Each gesture has a different handler in the flow / script.

The pluses are here physical buttons as fallback (Sleep Manual, Home Reset). Single press, double press, hold = different events. Rarely used, but when needed, works without Wi-Fi and without a cube.

Daily operation

How drivers work during the day

I don't touch most of the day — the context decides for me. The driver is for exceptions.

  1. In the morning

    Cube in "TV mode" side

    After waking up, I turn the cube to side 3 = TV channel control. Rotate = channel up/down (key_channel_up / key_channel_down). Single tap = TV mute toggle. Bug v1.10 had wrong capability ID (channel_up without prefix), fix v1.11.

  2. Day

    Cube on side 2 = audio volume

    Side 2 = active speaker volume control. Rotate left/right sends cube_rotate event with delta ±. The script will recalculate to the new volume, setCap to the speaker zone according to the active TOD.

  3. Evening

    Tap at comfort suggestion

    AI coordinator evaluates evening_idle → TTS suggest. User answer = tap on cube = accept (sh_user_intent_request='accept'). Without tap, suggest is ignored (after bathroom misroute fix).

  4. Sleep

    Sleep manual button

    Hard physical button next to the bed. Single press → sh_spim='yes' + sleep_brain cleanup. Double press → emergency lights ON (if anything). Hold 5 s → reset all sleep state vars.

Scenes

Five specific interactions

Each side of the die = different role. Some live, others planned.

1

Page 1 — IDLE

Default. No gesture inactive. It sits on the shelf whenever I can turn to something else. cube_face=1 + tap = nothing.

2

Page 2 — VOLUME

Audio volume control of the active speaker. Rotate ± delta → setCap volume_set. Tap = mute toggle. Target speaker according to TOD: kitchen in the morning, bedroom in the evening.

3

Page 3 — TV CHANNELS

TV remote shortcut. Rotate = channel up/down (key_channel_up), tap = mute, hold = power toggle. Bug fix v1.11 (3 weeks old) — channel capability prefix.

4

Page 4 — LIGHT SCENE

Cyclically switches light scenes — bright / dim / mood / off. Tap = next scene. Rotate = brightness fine-tune active scene. Planned, still in test.

Tap during suggest

AI coordinator → comfort_suggest → TTS reads the suggestion. User tap within 30 s window = accept → sh_user_intent='accept' → the scene performs. No tap ignored.

For the tech-savvy

What's going on under the hood

Cube event model, side dispatch, capability remapping.

Cube event model (face vs. rotate vs. tap)

Aqara Cube emits 3 different events via Homey capabilities:

  • cube_face: value 1-6, changes to flip action. It is states, not event — holds the current page until the user flips.
  • cube_rotate: event with delta in degrees. Positive = clockwise, negative = counter-clockwise. Sample over ~10° increment, so rotation = sequence of events.
  • cube_tap: one-time event. Single tap. Double tap is not native, we simulate over 2× tap in a 500 ms window.

Side dispatch is in sh_cube_dispatcher_v1 — switch (cube_face) on event type, route to specific handlers (volume, channel, light scene).

TV channel capability bug (3 weeks diagnostics)

Bug 2026-04-20 resolved: cube page 3 = TV channels, but rotate did nothing. Several hypotheses:

  • Cube doesn't have a rotate event in that side? (false — events in EventLog were)
  • TV not responding? (false — manual setCap worked)
  • Capability remapping? (true — root cause)

Cube_dispatcher had setCapabilityValue('channel_up'), but Android TV driver capability is key_channel_up (with prefix). No error, just silent ignore. Fix v1.11: channel_up → key_channel_up.

Memory: todo_cube_tv_channels.md — solved record.

User intent capture window

Comfort suggested pipeline:

  1. AI coordinator: situation = comfort_suggest, level 4
  2. TTS reads the suggestion: "Do you want to start a relaxation scene?"
  3. 30 s capture window for user_intent_request
  4. If cube_tap ARRIVES during window → sh_user_intent_request='accept'
  5. If nothing → window expires, sh_user_intent_request='timeout_idle'
  6. The down stream action (scene) only runs when 'accept'

Without this bypass window, the AI coordinator would activate scenes by itself → bug 25.4. (bathroom radio misroute). Fix v1.8 added an explicit accept guard.

Battery management (cube + button)

Aqara Cube has two CR2032 batteries, life ~24 months with typical daily activity (5-10 gestures/day). Sleep manual button has AAA, ~12 months.

Brain Guardian is watching measure_battery:

  • < 30% — log warning
  • < 15% — push alert (when implemented)
  • < 5% — critical, replacement required

After replacing the battery new UUID (silent fail flow trigger). Necessary re-pair check — diagnosis GET /api/manager/devices/device/<old> → 404.

Fallback chain (cube → button → mobile → manual override)

Fault tolerance design — when the primary controller fails, the lower layers go:

  1. Cube — primary (gestural, no app)
  2. Sleep manual button — for sleep state (beside the bed)
  3. Mobile Homey app — full UI, debugging, schedule editor
  4. Kiosk dashboard — RPi WaveShare 1024×600, touch
  5. REST API directly — last resort (PUT /capability/setCapabilityValue)
  6. Physical light switches — when none of the above works
