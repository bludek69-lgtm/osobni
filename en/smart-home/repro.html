📦 Devices · Speakers

Loudspeakers in the household

I use speakers in the kitchen, bathroom and bedroom according to the specific situation. Morning information belongs somewhere, afternoon radio somewhere else. This page explains room selection and equipment limitations.

Technical details

Three Google Cast endpoints (kitchen, bathroom, bedroom) plus Nest Hub Max in the bedroom as a visual + audio hybrid. No multi-room sync — instead context-aware routing: morning briefing to the kitchen, afternoon radio to the bathroom, evening music to the bedroom.

What does it do?

Speakers with a role

Three speakers in the apartment, each in its own zone — kitchen, bathroom, bedroom. All of them Google Cast compatible, so Homey can send audio stream directly (TTS, radio URL, music). Plus Nest Hub Max in the bedroom which has a display and a camera, double role (audio + visual alerts).

Speakers are not multi-room synced. Instead context-aware routing — audio_brain dispatcher decides the target speaker according to TOD and active zone: morning briefing to the kitchen (where coffee is being prepared), afternoon radio to the bathroom (shower), evening music to the bedroom. Sync is not needed, there is one user in one time zone.

Capabilities API via Homey: speaker_playing, speaker_track, volume_set, volume_mute. Custom radio URLs (Italian Classic Hits Sanremo TuneIn) go through speaker_track value = stream url .

Daily operation

Which speaker when

Routing is not random — it is deterministic according to the TOD + zone.

  1. In the morning

    The kitchen is dominant

    03:15 / 03:30 briefing to the kitchen speaker. The kitchen is the center of ritual — coffee, preparation. Speaker volume mid (60) to wake up but not wake up the neighbors. TV mute pipeline concurrently.

  2. Shower

    Bathroom radio

    Motion in the bathroom + TOD in the morning → starts Italian Classic Hits Sanremo. Stop at motion_off + 30 s timeout. Higher volume (75) to compete with water. Prev_playing guard prevents resume without explicit play.

  3. Day

    Idle

    sh_audio_request='idle'. Speakers only work as TTS recipients for alerts (anti-freeze, water leak, brain guardian warnings). Mostly silence.

  4. Evening

    Bedroom + Nest Hub Max

    Comfort suggest (AI coordinator) → Nest Hub Max in the bedroom. Visual prompt on the display + audio. User can accept via Cube. Music (Spotify cast) goes to the speaker's bedroom in parallel.

For the tech-savvy

What's going on under the hood

Cast capability API, dispatcher routing, TV mute pipeline.

Cast capability API

Homey via Google Chromecast app exposes:

  • speaker_playing: boolean — start/stop playback
  • speaker_track: string — Stream URL or name
  • speaker_artist: string — read-only metadata
  • speaker_album: string — read-only
  • speaker_position: float 0–1 — track position
  • volume_set: float 0–1 — volume level
  • volume_mute: boolean — mute toggle
  • volume_up / volume_down: trigger events

TTS goes through speaker_track as data URI or TTS endpoint URL (Google Cloud TTS gen → MP3 → cast).

Audio brain dispatcher routing

sh_audio_brain_v2 the target speaker decides according to:

  1. User explicit zone: if sh_audio_target_zone a hundred
  2. Active zone: most current motion / presence (max(open, kitchen, bathroom, bedroom))
  3. TOD default: morning=kitchen, shower=bathroom, evening=bedroom
  4. Fallback: kitchen speaker (central, audible from anywhere)

Decision logged in EventLog: audio_dispatch event with zone + speaker + reason. Searchable in JSONL on SSD HA RPi (as of 5/27/2026; formerly Google Sheets).

200 char TTS limit + briefing split

The Google Cast SDK has a hard limit of 200 characters per utterance. Longer = stream falls or truncates in the middle of a sentence. Defensive truncation v sh_gemini_brain_v1::sayTTS(): 

if (cleaned.length > 200) {
  cleaned = cleaned.substring(0, 200);
  logMsg('GOOGLE CAST: message truncated to 200 chars');
}

Briefing split into 2 phases:

  • briefing (3:15) — greeting, time, date, weather, holiday (max 150 chars)
  • briefing2 (+15 min) — BTC, PM2.5, humidity, funny comment (max 170 chars)
TV mute / unmute pipeline

Before each TTS:

  1. Read TV state (Android TV remote, IP 192.168.1.xxx)
  2. If volume > 0 → setCap volume_mute = true, save original volume
  3. Starts TTS
  4. Mon tts_completed: setCap volume_mute = false, restore volume

Without this, the TTS voice would compete with the TV sound — the morning news + briefing could not be heard. Capabilities volume_mute is toggle, no need to wait for driver ack.

Sleep guard for speakers

Sleep state active → priority engine denied for TTS (priority 100) if there is no critical bypass:

  • Briefing: blocked until unset (3:15 unlocks sh_spim)
  • Comfort suggested: blocked all night
  • Critical alerts: anti-freeze, water leak, gas → bypass
  • Bathroom radio: blocked (motion at night → bathroom router dim, no radio)

Critical bypass goes through sh_safety_bypass='yes' short-circuit in priority engine.
