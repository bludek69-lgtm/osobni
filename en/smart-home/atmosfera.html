CSENIT

🏠 Experience · Atmosphere and scenes

The house which feels part of the day

Morning, work, evening and sleep need different light and sound. Here I show how the behavior of the apartment changes depending on the part of the day and how I make sure that the evening peace is not interrupted by inappropriate automation.

Technical details

Three states, four phases of the day, one central sleep guard. It wakes you up slowly in the morning, lets you work during the day, offers peace in the evening, and quiets down at night. No explicit "scenes" in Homey UI — everything runs via time-of-day and state-aware logic in scripts.

What does it do?

The mood cannot be set, only recognized

Instead of "scenes" in Homey UI — where the user clicks "Movie Mode" and something happens — it's here state-aware layer. The system itself recognizes if it's morning before the alarm clock, if I'm currently sleeping, if I'm in relaxation mode after work, if it's late in the evening. Everything else is derived from this: lights, heating, audio, notifications.

The central variable is sh_spim ('yes' / 'no'). When it is 'yes', all 5 subsystems (lights, audio, heating, robot, alerts) automatically dim or turn off completely. There are three set/unset points: Sleep Manual button (Aqara Cube), Wake up Kitchen motion (waking), phone geofence.

It runs above sleep state three brain scripts: morning_brain (morning ritual), sleep_brain (evening shutdown), AI coordinator (situation classifier — morning briefing, evening comfort suggest). None of them are "scenes" — they are handlers responding to time + state + presence.

Daily operation

Four phases of the day

The context changes continuously. Boundary moments have their own handler.

  1. 02:45

    Pre-wake

    Heating layer 1 starts 30 minutes before the alarm — bathroom +2 °C, toilet +1 °C. Sleep state still 'yes', lights still dark. The system prepares, but does not interrupt.

  2. 03:15

    Wake & briefing

    Alarm time → morning_brain: ensureHeatingMorningMode (preset=home), TV mute, phase 1 briefing to the kitchen. Sleep state is disabled during motion in the kitchen. 03:30 phase 2 briefing.

  3. Day

    Active

    Light routing according to lux + presence, audio idle, heating according to schedule + AI layer. No automatic scenes — each subsystem handles its context independently. The AI ​​coordinator monitors, but most of the time silently.

  4. Evening

    Comfort phase

    AI coordinator can evaluate "evening + idle scene" → comfort_suggest. TTS will read the suggestion, not auto-execute (after bathroom misroute fix). Privacy guard on — shutter up = open space lights blocked.

  5. 22:00+

    sleep prep

    He already took over the heating night slot from the schedule (10 p.m.). Sleep_brain during sleep confirm: preset boost→home reset, audio mute, robot blocked. sh_spim='yes' gate for the whole night.

Scenes

Five Rituals of the Day

Triggered from time + state + presence. Manual override only exceptionally.

Morning

Alarm → morning_brain → heating preset=home + boost bathroom 23 °C 60 min, TV mute, briefing phase 1+2. Goal: introducing the day slowly, no shock.

Day

Default state — no scene, only reactive subsystems. Lux controls the lights, schedule controls the heating, audio idle. Brain Guardian runs once every 15 min.

Evening

AI coordinator detect "evening + idle" → comfort_suggest TTS. Privacy guard active (blind > 20% blocks open lights). Possible relaxation scene when user accepts (Cube / voice).

Sleep

Sleep button (Cube) or manual flow → sh_spim='yes' → sleep_brain cleanup (boost reset, audio mute, robot block). The Schedule night slot already keeps temperatures lower.

Night

Sleep state active. Motion in the bathroom has its own dim mode (bathroom router dim mode). Critical alerts (anti-freeze, gas, water) override via safety bypass.

Hardware

What determines the atmosphere

It's not hardware in the standard sense — it's a composition of sensors + scripts.

Aqara Cube T1 Pro

User intent · gestural · Zigbee

A six-sided cube. Each side = different mode. Rotation = volume change. Knock = trigger. Main user input for "accept comfort suggest" / "sleep manual" / etc. Fixed TV channel bug v1.11 (channel_up → key_channel_up).

Aqara FP2

Presence · sleep wake detection

Detects a calm person. For atmosphere logic like sleep_wake marker — when the bedroom starts to move (wake up) vs. rest (sleep). Plus open space presence for evening comfort detection.

Morning + Sleep brain

Scripts · sh_morning_brain_v1 · sh_sleep_brain_v2

Two orchestrators — morning ritual and evening cleanup. Each keeps 5+ subsystems in sync. Morning: heating + audio + TV. Sleep: heating reset + audio mute + robot block + sleep state set.

Phone geofence

Mobile app · GPS · radius 100 m

Home/away detection. Multi-signal confirm with motion in 5 min window. Trigger for preset switch + sleep state suggest (when alone at home and 22+ h).

AI Coordinator

sh_ai_coordinator_v1 · cron 5 min

Classifies the current situation (idle, busy, evening_idle, morning_prep, comfort_suggest). Input for AI brain and comfort_suggest TTS. Levels 0–5, level 4 = TTS suggest.

For the tech-savvy

What's going on under the hood

Sleep state architecture, brain handlers, AI coordinator levels.

Sleep state (sh_spim) — central gate

The only variable that gates 5 subsystems. sh_spim='yes':

  • Light: priority engine days → darkness
  • Audio: TTS denied (except critical), radio blocked
  • Heating: night slot already active from schedule (informative)
  • Robot: cannot run, queued requests are waiting
  • Brain Guardian: increased tolerance for motion (anti-false-positive)

Set points: Sleep Manual (Cubo button), Wake up Kitchen (motion at unusual hour implies waking), Phone geofence (alone home + late hour). Sync with native Homey presence API set_asleep / set_awake — never delete as a duplicate.

Morning brain (ensure*Mode functions)

sh_morning_brain_v1 v3.5+ has 4 ensure functions, each of which is called by flow during alarm / motion / fallback:

  • ensureHeatingMorningMode() — preset=home, bathroom boost 23 °C 60 min
  • ensureAudioMorningMode() — TV mute, briefing trigger via sh_gemini_mode
  • ensureLightsMorningMode() — dim kitchen, open space according to FP2
  • ensureSleepStateUnset() — sh_spim='no' (gate released)

Each function is idempotent — they can be called multiple times during the ritual, the result is the same. No state mutation except desired-state writeback.

Sleep brain (evening cleanup)

sh_sleep_brain_v2 v3.1+ triggered when Sleep button / late-evening auto-detect:

  • ensureHeatingSleepMode() — boost preset reset (boost→home), schedule night slot takes over
  • ensureAudioSleepMode() — all stop, prev_playing flag clear
  • ensureLightsSleepMode() — fade out 5 s, then off
  • ensureRobotSleepMode() — block + cancel queued cleaning
  • ensureSleepStateSet() — sh_spim='yes' (gate activation)
AI coordinator levels (situation classifier)

sh_ai_coordinator_v1 cron 5 min evaluates 6 situations:

  • Level 0 — idle: nothing happens, no action
  • Level 1 — passive_observe: motion but no intent change
  • Level 2 — context_log: boundary moment (sunrise / sunset / alarm)
  • Level 3 — passive_notify: log to EventLog, no TTS
  • Level 4 — comfort_suggest: TTS suggest (evening + idle scene)
  • Level 5 — proactive_action: auto-execute (only after user accept)

Bug 25.4. — level 4 started bathroom radio by itself without user accept. Fix: prev_playing guard v sh_tts_resume_exec_v1 v1.8.

Time-of-day buckets (4 phases)

No explicit "scene" — just a TOD bucket that subsystems read:

  • night (22:00–05:00): sleep gate likely active, low temps, no audio
  • morning (05:00–10:00): briefing window, bathroom boost, audio active
  • day (10:00–18:00): default reactive, lux controls lights, idle audio
  • evening (18:00–22:00): privacy guard active, comfort suggested possible

Context grants are not hard-coded in scripts — they are read from the configuration sh_cfg_tod_*_start. Seasonal adjustments (winter/summer time) go via config update, not code.
