📦 Equipment · Infrastructure

Facilities for running a household

In addition to the Homey headquarters, I use other devices and tools for records, backups and traffic control. This page shows their roles and how I troubleshoot.

Technical details

Homey Pro is the main hub, but it's not alone. Raspberry Pi, Home Assistant, GitHub repo and GitHub Actions form a backup + observability layer that makes the system reliable outside the local network.

Raspberry Pi (kiosk + proxy)

Raspberry Pi 4 with WaveShare 10.1" HDMI LCD (1024 × 600). Runs 24/7 in the lobby as an always-on dashboard touch kiosk. Chromium in full-screen kiosk mode, autostart via systemd.

Second Role: proxy dashboard. Python script dashboard_server.py on localhost:8080 switches requests from the dashboard to the Homey REST API. This way, the dashboard works even if the Homey cloud is unavailable — a local network is enough.

Third role: other services. Tailscale (access from work via VPN), Apps Script proxy, or other scripts.

Home Assistant (mirror + observer + 24/7 sandbox gateway)

Second Raspberry Pi s Home Assistant OS. The main role is not primary management (that's what Homey does) — the HA is read-only observer, backup target and from May 14, 2026 also a 24/7 test gateway via Python sandbox runner.

Specifically:

  • HA Energy Dashboard aggregates data from Shelly plugs (fridge, oven, microwave).
  • Long-term storage telemetry — Homey has a short memory, HA lasts for years.
  • Separate backup target for git repo (cron auto-pull every hour).
  • Failover: if Homey goes down, HA knows the current state.
  • NEW (May 14): Python sandbox runner runs every hour over HA shell_command + automation. 26 tests, 19 replay scenarios, auto-registries of new entities. Without it, no repair is allowed into live Homey.
  • NEW (May 14): Dashboard cache pipeline (Python, cron 1×/min) → /local/smart-home/dashboard-data.json as a mirror+enhance layer between Homey and the frontend. It reduces the Homey HTTP load, the kiosk reads the cache instead of directly.
  • LIVE from 5/27/2026: Intenso SSD Premium 256 GB USB 3.2 installed as /dev/sda1 (~234 GB ext4). Hybrid setup: SD card remains OS, SSD holds EventLog JSONL (primary logging layer), HA recorder DB, backups, sandbox and git mirrors. The goal was to extend the life of the SD (HA recorder does hundreds of writes/min, SD has 3-10k cycles, SSD 1M+) — accomplished.

Communication: HA accesses Homey via REST API (Bearer token), Homey accesses HA via webhook + REST sensor. No dual control — just shared observability.

GitHub repos (single source of truth)

All code, documentation, snapshots and configuration in private GitHub repos. Three active:

  • smart-home-homey — all of them sh_* scripts, audits, deployment plans, daily export snapshots from the Homey REST API.
  • smart-home-dashboards — HTML/CSS/JS dashboards in all resolutions + Python phase patchers.
  • lk-finance — private finance (encrypted-at-rest via transcrypt + AES-256-CBC + PBKDF2). Same pattern, different data.

Daily backup pipeline: HAOS script backup_homey.sh runs every day at 02:00, calls the Homey REST API, exports devices/variables/flows/scripts, commits to backup_homey/ and push to GitHub. SSH deploy key, no stored token in repo.

GitHub Actions (automated actions)

Part of the tasks are running in the cloud on GitHub Actions, ne na Homey. Specifically:

  • daily_backup.yml — daily Homey state snapshot, cron on GitHub side (failover if HAOS goes down).
  • weekly_audit.yml — weekly static analysis of scripts: looks for hardcoded names, missing guards, deprecated patterns. Creates an issue.
  • memory_watchdog.yml — monitors memory files, if there is duplication / stale info → alert.
  • cleanup_phase4_delete.yml — scheduled auto-delete cleanup wave scripts. Pre-checks: Brain Guardian score, EventLog exceptions. If red flag → action fails, no delete.

Advantage: the action runs outside the house. Even if Homey goes down, GitHub Actions still monitor the repo and execute scheduled actions. Tokens are in GitHub Secrets, not code.

Finance (parallel private stack)

Same pattern as smart home, but for personal finance: private GitHub repo + HAOS mirror. Key Difference — encryption-at-rest.

Files of type *.pdf, *.xlsx, *.csv, *.docx, *.zip are encrypted before commit transcrypt + AES-256-CBC + PBKDF2 (100k iter). GitHub can only see U2FsdGVk... blobs, no plaintext. Master password locally, outside the repo, offline backup to USB + paper in the safe.

Nothing from the website belongs here — finances are strictly private. But the architecture is shared: same auto-backup pattern, same principles, only higher data protection.
