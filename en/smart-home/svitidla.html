Overview of lights and light fixtures

Overview of ceiling, table and other lights in the apartment. Different brands and connection methods are connected by Homey so that common rules can apply to them.

Technical details

Ceiling, table, ambient LED, bathroom, hall. Mixed from different eras and brands — Wi-Fi (Tuya), Zigbee (IKEA, Aqara), Z-wave (Fibaro). Common only through Homey as an orchestrator and a 4-layer pipeline (request → priority → router → setCap).

What does it do?

Luminaires as an action layer

There are lamps output layer system. Sensors, scripts, AI layers will do all the work, but the final action is always the same — capability setCapabilityValue('onoff', true/false) or setCapabilityValue('dim', 0.0–1.0) on a specific device. This ends the entire pipeline.

Heterogeneous hardware. Sector 1 is Wi-Fi (Tuya integration via Homey), the LED strip behind the TV is Zigbee, the bathroom ceiling is a Z-wave dimmer (Fibaro), the table lamp Dining table 1 is Wi-Fi. From a scripting perspective, it doesn't matter — the capability API is unified.

4 functional roles: main (Sector — primary lighting), accent (Table, LED strip — atmosphere), task (bathroom ceiling — functional space), way-finding (hallway, portable — orientation). Each role has different activation rules.

Functional role

Four roles, four rules

Same hardware, different context — different power-up logic.

  1. Main

    Sector1 — primary

    Main ceiling light open space (dining room + kitchen). Boolean on/off, full output. Privacy guard: blind > 20% blocking. Sleep guard: night darkness. Wi-Fi (Tuya), capability onoff.

  2. Accent

    Dining room table + LED strip

    Atmosphere. Table lamp above the dining table + LED strip behind the TV. The same privacy guard as Sektorka. When the lux is below the threshold, they turn on with presence, otherwise they are off.

  3. Task

    Bathroom ceiling

    Functional space. Z-wave dimmer (Fibaro), capability dim 0–1. Full bright in the morning (briefing window), dim 0.2 at night. Bathroom router has its own dim profile (softer wake-up).

  4. Way-finding

    Anteroom

    Orientation. Auto-on when motion + lux below threshold. 60 s timer, then off. Independent of privacy / sleep guard — a way to find the way from bed to the kitchen without waking up the whole apartment.

For the tech-savvy

What's going on under the hood

Capability API, comparison protocol, dim curve, scene management.

Wi-Fi vs. Zigbee vs. Z-wave (why everything)

Historically, they were added according to availability — Sektorka was Tuya (Wi-Fi from the e-shop), LED strip Zigbee (trend monitoring), bathroom Z-wave (Fibaro ecosystem). Functionally, the difference is minimal, the API capability is unified via Homey.

  • Wi-Fi (Tuya): cheap, wide selection, but cloud dependent (occasionally ~1s latency). Sector, Table, vestibule.
  • Zigbee: local, mesh, small overhead. LED strip behind the TV. Battery-free Zigbee lights = bridge.
  • Z-wave: local, dedicated band, good through walls, but more expensive. Bathroom Fibaro dimmer (kept wall switch for fallback).
Capability API (onoff vs. dim)

Homey unifies light capabilities:

  • onoff: boolean, on/off only. Wi-Fi Tuya, most cheap lights.
  • dim: float 0.0-1.0. Z-wave Fibaro, Zigbee with dim support.
  • light_hue: 0.0–1.0 ~= 0–360°. RGB / RGBW strip.
  • light_saturation: 0.0–1.0. Color saturation.
  • light_temperature: 0.0-1.0 ~= 2700K-6500K. Warm vs. cool white.
  • light_mode: enum 'color' / 'temperature'.

The light router reads the capability list per device and selects the best match. Boolean only onoff, color request goes through hue/saturation if the capability exists.

Dim curve (linear vs. perceptual)

Linear 0.5 = 50% power, but the human eye perceives logarithmically — 50% power looks like ~75% brightness. For "dim 50%" which looks like half brightness, mapping perceptual: 

dimPower = Math.pow(dimPerceptual, 2.2);
// dimPerceptual=0.5 → dimPower=0.22
// dimPerceptual=0.7 → dimPower=0.46

Currently, the light router uses linear mapping (simplicity). Perceptual mapping in the plan if the user feels the need (dimming feel is enough).

Sleep guard for the bathroom (fine profile)

Bathroom has its own dim profile for a night's sleep-without-waking:

  • Day: dim 1.0 (full bright), 5 min timer off
  • Evening: dim 0.7, 5 min timer
  • Night (sh_spim='yes'): dim 0.2 (warm low), 3 min timer
  • Pre-wake (3:00-3:15): gradual ramp 0.2 → 0.6 in 1 min

The bathroom router doesn't recognize the global sleep_guard deny — instead it has a soft path that lights up but dimly at night. The user sees, but does not fully wake up.

Scene management (if any)

The scene would be preset capabilities for a group of lights — e.g. "Movie" = Sector off, Table 0.3 dim warm, LED strip warm orange, bathroom off. Currently NOT IMPLEMENTED — context (TOD + presence + sleep) decides individually, not as a scene.

Plan for Phase D (Expansion atmosphere): scene as preset in EventLog (history-based learning), AI coordinator can suggest ("do you see the music + evening + TV on → Movie scene?").
