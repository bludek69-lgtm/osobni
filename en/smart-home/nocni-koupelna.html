📖 Story · Case study

Night bathroom at 3 in the morning

A short trip to the bathroom at night should be lit only by a soft light. It doesn't have to start the radio or the whole morning routine. Here I show how I distinguish this passage from the actual rising.

Technical details

You get up at night to go to the bathroom. No classic motion-on-trigger would work here — full light would wake you up, the briefing would sing into your quiet apartment, the robot vacuum cleaner would start running. Instead, a subtle path: dim 0.2, no TTS, no subsystems awake. Then back to bed, sleep state intact, you continue the REM cycle.

Context

Tuesday 02:47, sleep state active

Condition: sh_spim='yes' from 22:35. Heating in the night slot (dining room 18, bedroom 17, bathroom 19, toilet 16). All lights off. Audio silent. Robot vacuum cleaner blocked. Brain Guardian increased motion tolerance. Roll down to 0.1.

Trigger: you get up to go to the toilet. Motion in the bedroom (Aqara FP2 detects), then motion in the bathroom (PIR Z-wave). 3 minutes of interaction, then motion in the bedroom back. No hard wake-up — sleep brain detects the difference between "waking up" and "toilet trip".

What should NOT happen: full light (it would wake up the rest of the night), TTS briefing (the script would not have a trigger but it could), heating mode change (unnecessary disruption of the schedule), start the robot vacuum cleaner (acoustic shock), comfort suggest (obviously not at night).

    PIR vestibule → way-finding light auto-on, dim 0.2 (night profile, not default 0.8). Lux check overridden — way-finding has its own rules. 60 s timer for off.

    Bathroom router: sleep state active + TOD night → dim profile 0.2 (warm low color temperature 2700 K). NO radio. NOT full light. Ceiling Fibaro dimmer setCap dim 0.2.

    3 minutes activity

    Bathroom motion continuous, dim holds 0.2. No action except continuity. The vestibule timeout has expired (60 s) → off (the vestibule has no motion). Brain Guardian cron 02:50 — state consistent (sleep + bathroom_active = ok).

  6. 02:50:10

    Bathroom motion off

    30 s grace period begins (motion may flash). After 30 s bathroom router stop: dim 0.2 → fade out 5 s → 0. No hard cut, gentle ramp so your eyes don't go into shock.

  7. 02:50:55

    Way back → way-finding light again dim 0.2. Same 60s timer. FP2 in the bedroom takes over detection.

  8. 02:51:05

    You went back to bed. FP2 detect presence, sleep brain still holds sh_spim='yes' (motion period was < 5 min, classify as bathroom trip). No action — sleep gate intact.

    Hallway motion 60 s back ago → way-finding off. Total darkness again. The heating schedule continues in the night slot, the boiler runs in its standard routine.

  10. 02:52+

    The REM cycle continues

    Never hijack the sleep state. No subsystem was fully rerun. The briefing at 3:15 will take place normally according to the schedule. The user may not even remember in the morning that he got up at night — that's the goal.

The difference

What would a poorly built system do

Subtlety = quality user experience. Naive logic = miserable night.

Full light

A naive motion-trigger would trigger the bathroom to dim 1.0 (full bright). 600 lux into the eyes at 03:00 = REM disruption, an hour of sleep destroyed. Instead, 0.2 = ~50 lux warm. You see what you're doing, the eyes don't go into shock.

Audio briefing

If the sleep brain interpreted the motion as a wake-up → the TTS briefing would start. A voice in a quiet apartment at 03:00 = adrenaline spike. Instead, the sleep guard keeps the audio silent all night.

Heating boost

A naive system could interpret motion as coming to the bathroom in the morning → boost preset (23 °C 60 min). Unnecessary at night, the boiler would run an extra hour. Instead, the schedule night slot continues.

Robot vacuum cleaner

A naive auto-cleaning trigger could start the robot on motion at 03:00. Acoustic attack. Instead, the robot is blocked for the entire sleep window (sh_robot_blocked='yes' until sleep gate active).

Door-open detection

You open the bathroom door → door_contact event. He could naively interpret it as "someone entered/leaves" → away/home preset. Brain Guardian bypass this: door_contact + sleep_state = active → ignore preset cascade.

For the tech-savvy

What's going on under the hood

Sleep brain heuristic (bathroom trip vs. wake-up)

The sleep brain decides whether the motion in the sleep window is "wake" or "bathroom":

  • Wake-up signs: motion duration > 5 min, multiple zones, alarm time approaching (< 30 min), explicit unblock signal (Cube tap, button press)
  • Bathroom trip signs: motion 1–4 min, single round-trip path (bedroom → bedroom → bathroom → bedroom → bedroom), no time proximity alarm, no explicit unblock
  • Edge case: motion 4–5 min = uncertain, keeps sleep state but logs warning

Classification is rule-based, not ML. ML would need labeled data (user feedback "it was a bathroom trip / waking up") which we don't have. Rules are adjusted once every few months according to observed patterns.

Bathroom router night profile 
// sh_bathroom_router_v1 (excerpt)
function getBathroomProfile() {
  if (sh_spim === 'yes') return 'night';      // dim 0.2 warm, 30s grace
  if (TOD === 'morning') return 'bright';     // dim 1.0, 5min timer
  if (TOD === 'evening') return 'normal';     // dim 0.7, 5min timer
  return 'normal';
}
const profile = getBathroomProfile();
const target = PROFILES[profile];
await stropniDimmer.setCapabilityValue('dim', target.dim);
if (profile === 'night') {
  await fadeOut(5000);  // smooth ramp on motion-off
}

Profile night has dim 0.2 + warm color temperature (if there was light_temperature capability). Currently only dim. Plan: add light_temperature setCap if the bathroom ceiling supports it (Fibaro FGD-212 supports it, it is not fitted with a warm-tunable bulb).

Way-finding light (independent path)

Hall lights have their own rules, separate from other zones:

  • Bypass sleep guard (sleep_state ignored — way to find the way)
  • Bypass privacy guard (hallway has no outside view)
  • Custom night profile (dim 0.2 warm, 60s timer)
  • Door_contact open trigger plus motion trigger

Without way-finding, the user would either have to feel the switch by the door (classic solutions) or use a mobile flashlight. Smart home adds value here that other solutions would not have.

Audio bypass for night (except critical alerts)

Night audio gate has 4 categories:

  • Suppressed: TTS, briefing, comfort suggest, radio. Default sleep state.
  • Whisper bypass (planned): critical info (delay alarm 1h?, weather alert) read quietly in the bedroom. Volume 0.2, max 100 chars. Currently not implemented
  • Critical bypass: anti-freeze, water leak, gas, smoke. Full volume, kitchen speaker (central).
  • Emergency siren (planned): smoke/gas → siren on all speakers, max volume. Alert mode.
Brain Guardian motion tolerance at night

Brain Guardian has anomaly detection on sleep_state inconsistency: 

// daytime tolerance: motion_count > 3 in 5min while spim=yes = wake suspect
// nighttime (sleep window 22:00-05:00) tolerance: > 8 in 5min = wake suspect
const tolerance = isInSleepWindow() ? 8 : 3;
if (motionCount5min > tolerance && sh_spim === 'yes') {
  logEvent({event: 'sleep_anomaly_motion_count', count: motionCount5min});
  // does NOT auto-unset sh_spim — just logs warning
}

A bathroom trip typically has 4–6 motion events in a 5 min window (entry, use, exit). Below tolerance, no alert. When the motion is much more (8+) and no cube/button trigger, something unusual happens.
