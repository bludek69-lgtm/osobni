📦 Attrezzature · Infrastrutture

Strutture per la gestione della famiglia

Oltre alla sede centrale di Homey, utilizzo altri dispositivi e strumenti per registrazioni, backup e controllo del traffico. Questa pagina mostra i loro ruoli e come risolvo i problemi.

Dettagli tecnici

Homey Pro è l'hub principale, ma non è il solo. Raspberry Pi, Home Assistant, GitHub repo e GitHub Actions formano un livello di backup + osservabilità che rende il sistema affidabile al di fuori della rete locale.

Raspberry Pi (chiosco + proxy)

Lampone Pi4 con WaveShare 10,1" HDMI LCD (1024 × 600). Funziona 24 ore su 24, 7 giorni su 7 nella hall come un chiosco touch sul dashboard sempre attivo. Chromium in modalità chiosco intero a schermo intero, avvio automatico tramite systemd.

Secondo ruolo: dashboard proxy. Scrittura Python dashboard_server.py su localhost:8080 passa le richieste dalla dashboard all'API REST Homey. In questo modo la dashboard funziona anche se il cloud Homey non è disponibile: è sufficiente una rete locale.

Terzo ruolo: altri servizi. Tailscale (accesso dal lavoro tramite VPN), proxy Apps Script o altri script.

Assistente domestico (mirror + osservatore + gateway sandbox 24 ore su 24, 7 giorni su 7)

Secondo Raspberry Pi Sistema operativo Home Assistant. Il ruolo principale non è la gestione primaria (questo è ciò che fa Homey): lo è l'HA osservatore di sola lettura, destinazione di backup e dal 14 maggio 2026 anche un gateway di test 24 ore su 24, 7 giorni su 7 tramite il corridore sandbox Python.

Nello specifico:

  • HA Energy Dashboard aggrega i dati dalle prese Shelly (frigorifero, forno, microonde).
  • Telemetria di archiviazione a lungo termine: Homey ha una memoria breve, l'HA dura per anni.
  • Destinazione di backup separata per repository git (estrazione automatica di cron ogni ora).
  • Failover: se Homey non funziona, HA conosce lo stato corrente.
  • NOVITÀ (14 maggio): Il runner sandbox Python viene eseguito ogni ora su HA shell_command + automazione. 26 test, 19 scenari di replay, autoregistrazioni di nuove entità. Senza di esso, non è consentita alcuna riparazione su Homey.
  • NOVITÀ (14 maggio): Pipeline della cache del dashboard (Python, cron 1×/min) → /local/smart-home/dashboard-data.json come livello mirror+enhance tra Homey e il frontend. Riduce il carico HTTP di Homey, il chiosco legge la cache invece che direttamente.
  • IN DIRETTA dal 27/05/2026: Intenso SSD Premium 256 GB USB 3.2 installato come /dev/sda1 (~234GB esterno4). Configurazione ibrida: la scheda SD rimane del sistema operativo, l'SSD contiene EventLog JSONL (livello di registrazione primario), DB del registratore HA, backup, sandbox e mirror git. L'obiettivo era prolungare la durata della scheda SD (il registratore HA esegue centinaia di scritture al minuto, la scheda SD ha 3-10.000 cicli, l'SSD 1M+): obiettivo raggiunto.

Comunicazione: HA accede a Homey tramite API REST (token portatore), Homey accede a HA tramite webhook + sensore REST. Nessun doppio controllo: solo osservabilità condivisa.

Repository GitHub (unica fonte di verità)

Tutto il codice, la documentazione, gli snapshot e la configurazione in repository GitHub privati. Tre attivi:

  • smart-home-homey - tutti quanti sh_* script, controlli, piani di distribuzione, istantanee di esportazione giornaliere dall'API REST Homey.
  • smart-home-dashboards — Dashboard HTML/CSS/JS in tutte le risoluzioni + patcher di fase Python.
  • lk-finance — finanza privata (crittografato a riposo tramite transcrypt + AES-256-CBC + PBKDF2). Stesso modello, dati diversi.

Pipeline di backup giornaliero: Scritta HAOS backup_homey.sh viene eseguito ogni giorno alle 02:00, chiama l'API REST Homey, esporta dispositivi/variabili/flussi/script, si impegna a backup_homey/ e invialo a GitHub. Chiave di distribuzione SSH, nessun token archiviato nel repository.

Azioni GitHub (azioni automatizzate)

Parte delle attività sono in esecuzione nel cloud su GitHub Actions, non su Homey. Nello specifico:

  • daily_backup.yml - snapshot giornaliero dello stato Homey, cron sul lato GitHub (failover se HAOS non funziona).
  • weekly_audit.yml — analisi statica settimanale degli script: cerca nomi codificati, guardie mancanti, modelli deprecati. Crea un problema.
  • memory_watchdog.yml — monitora i file di memoria, se sono presenti informazioni duplicate/obsolete → avviso.
  • cleanup_phase4_delete.yml - script di ondate di pulizia con eliminazione automatica pianificata. Controlli preliminari: punteggio Brain Guardian, eccezioni EventLog. Se bandiera rossa → l'azione fallisce, nessuna eliminazione.

Vantaggio: l'azione si svolge fuori casa. Anche se Homey non funziona, GitHub Actions monitora comunque il repository ed esegue azioni pianificate. I token si trovano in GitHub Secrets, non nel codice.

Finanza (stack privato parallelo)

Stesso schema della casa intelligente, ma per finanza personale: repository GitHub privato + mirror HAOS. Differenza chiave: crittografia a riposo.

File di tipo *.pdf, *.xlsx, *.csv, *.docx, *.zip sono crittografati prima del commit transcriptare + AES-256-CBC + PBKDF2 (iter da 100k). GitHub può solo vedere U2FsdGVk... BLOB, nessun testo in chiaro. Password principale localmente, fuori dal repository, backup offline su USB + carta nella cassaforte.

Niente del sito web appartiene a questo: le finanze sono strettamente private. Ma l’architettura è condivisa: stesso modello di backup automatico, stessi principi, solo una maggiore protezione dei dati.
