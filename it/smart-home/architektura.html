Come viene gestita la casa

Il movimento, l'ora o il ritorno a casa attiveranno la richiesta. Le regole di controllo valutano la situazione e solo allora cambiano la luce, il riscaldamento o altre apparecchiature. Di seguito descrivo come vengono separati questi passaggi e perché il sistema è meglio controllato.

Dettagli tecnici

Tutta la logica in un unico posto. Il flusso è l'innesco, lo script è il cervello, il router è il centralino, il dispositivo è l'output.

Flusso
Trigger (ora, sensore, pulsante)
Copione
Logica + valutazione multisegnale
Richiesta
Richiesta strutturata
Router
Priorità + indirizzamento
Dispositivo
Azione reale (luce, TRV, altoparlante)

12 regole che ho introdotto

Ogni regola nasce da un episodio specifico, non da una teoria. Ecco tutto ciò che tiene insieme il sistema oggi.

RIUTILIZZARE PRIMA

Prima di creare una nuova entità (script, flusso, variabile), controlla se ne esiste già una simile. Refactoring > nuovo codice.

PRIMA LA SCRITTURA

Flusso = trigger + imposta variabile + esegui script. Nessuna logica nelle carte Flow. La logica negli script è modificabile, debuggabile e testabile.

MAPPA DEL DISPOSITIVO

Nessun nome dispositivo hardcoded. Tutto finito sh_device_map_v1. Rinominare un dispositivo = una modifica, non 20 script interrotti.

MULTISEGNALE

Nessuna decisione critica da un singolo sensore. Sempre 2+ segnali indipendenti (FP2 + movimento Z-Wave, pulsante + geofence).

RISPETTO DEL SONNO

Nessun TTS, azioni rumorose o luci sh_spim=yes. Eccezioni: briefing mattutino, allarmi critici.

INTERBLOCCO DELLA PRIVACY

Tenda aperta → luci open space bloccate. Appartamento piccolo, i passanti possono vedere l'interno. Effetto Acquario.

RESET IN MINIMO

Ogni richiesta temporanea deve essere reimpostata su idle. Nessun ripristino = pipeline bloccata + nessuna radio al mattino.

PROTEZIONI PER LE FINESTRE

I trigger hanno finestre temporali: routine mattutina dalle 3:00 alle 10:00, notturna dalle 22:00 alle 6:00. Fuori dalla finestra, lo script si rifiuta di continuare.

NESSUN LANCIO

Mai throw new Error(). Sempre log + return false. Si verificano arresti anomali prima della pulizia, lasciando le variabili in uno stato incoerente.

CACHE VARIABILE

Ogni script memorizza nella cache le variabili (_varCache + _loadVars()). Nessuna cache = SIGABRT su oltre 200 variabili.

IDEMPOTENZIA

setCapabilityValue solo se il valore cambia effettivamente. Set cieco = cascata di trigger di flusso e carico non necessario.

NESSUNA REGRESSIONE

Prima di modificare uno script esistente: leggere tutto, verificare il chiamante, modifica minima. "Prima ha funzionato" = non andare oltre un forte bisogno.
